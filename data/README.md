# Catalog data

`catalog.json` is the source of truth for the inventory. The stable `id` is the key used by downstream tooling. `category` describes the main harness responsibility made visible by the workload, while `kind` distinguishes a task benchmark from a study, watchlist item, or runner/environment layer. `signals` is a set of capability tags. `grading`, `environment`, and `limitation` explain how to interpret the evidence.

The 2026-09-13 snapshot, corrected on 2026-09-14, contains 115 entries across 13 categories. Counts include benchmarks, studies, infrastructure, and watchlist candidates. An entry's resource type does not indicate that its claims were independently verified.

An optional `aliases` array preserves identifiers from merged records. Consumers should first match `id`, then look in `aliases`; count each entry once. For example, `shellbench` resolves to the retained ID `clawbench-openclaw`, whose canonical name is ShellBench (formerly ClawBench). The old and new GitHub repository URLs resolve to the same project. See the [correction log](../docs/updates.md).

`source-audit.json` is a point-in-time availability audit for the GitHub repositories referenced by the catalog. It records repository metadata and a SHA-256 hash of each README blob. It does not claim that the benchmark was independently reproduced and it never includes benchmark answers or credentials.

The JSON structure is described by [`catalog.schema.json`](catalog.schema.json). Run `python3 scripts/validate_catalog.py` after editing the catalog.

The [complete Markdown catalog](../docs/catalog.md) is generated by `python3 scripts/build_catalog_docs.py`. The root README is an editorial selection guide; it intentionally highlights fewer resources. Changes to record content should be made in JSON and propagated to generated exports.
